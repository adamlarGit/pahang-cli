# 014: T5.2 Implement FullReportPlanBuilder Deep Module

## Parent

[Full Report Generation Workflow Map](../map.md)

## Branch Strategy

Implemented directly on the single unified Full Report feature branch (no per-ticket branches).

## What to build

`FullReportPlanBuilder` deep module that evaluates substation equipment packages, testsheet specs, and ingested Quick Report parts to construct a complete, deterministic Bill of Materials (`FullReportStationPlan`) ordering all document parts 1 through 7 before compilation.

## Reuse Pointers

- `src/full_report/slicer.py`: Re-use `DocumentSlicer`, `SlicedReportParts`, and `CbmDefectSliceMetadata`.
- `src/full_report/interleaving.py`: Re-use `DefectInterleavingPolicy` for ordering and interleaving defect pages.
- `src/full_report/scan_adapters.py`: Re-use equipment scan adapters to build component scan page specs.
- `src/full_report/census.py`: Re-use `ExecutiveSummaryCensusBuilder` for Executive Summary Census BOM item.
- `src/core/normalizers.py`: Re-use `resolve_station_code()`, `format_month_folder()`.
- `src/testsheet/extractor.py`: Re-use `TestsheetExtractor` and `SubstationEquipmentPackage`.

## Allowed Scaffolding

- Deep module class `FullReportPlanBuilder` in `src/full_report/plan_builder.py`.
- Data structures in `src/full_report/plan_builder.py`: `PlanPartType` enum (`FRONT_PAGE`, `CENSUS`, `VI_SUMMARY`, `SCAN_PAGE`, `CBM_DEFECT`, `CONDITION`, `VI_DEFECTS`, `STICKER`), `PlanPartItem`, `FullReportStationPlan`.
- Unit test harness `tests/test_full_report_plan_builder.py` asserting exact BOM part sequence across various substation configurations (with and without visual defects, healthy vs defective overviews per D47).

## Acceptance criteria

- [ ] Evaluates component health to determine rendered vs sliced overview pages (D47).
- [ ] Assembles canonical 8-part sequence: Front Page $\to$ Census $\to$ VI Summary (if present) $\to$ Component Stream (with interleaved defects) $\to$ Substation Condition $\to$ VI Defect Pages $\to$ Sticker Page per D39.
- [ ] Omits `vi_summary.docx` and `vi_defect_pages.docx` cleanly if zero visual defects exist.
- [ ] Outputs strongly-typed `FullReportStationPlan` ready for composer consumption.
- [ ] Comprehensive unit tests verifying plan structure across benchmark topologies.
