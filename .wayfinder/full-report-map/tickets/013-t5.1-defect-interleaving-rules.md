## Parent

[Full Report Generation Workflow Map](../map.md)

## Branch Strategy

Implemented directly on the single unified Full Report feature branch (no per-ticket branches).

## What to build

`DefectInterleavingPolicy` module that matches sliced CBM defect pages (`temp_parts/cbm_defects/`) to physical equipment components using D37 grammar and Table 1 metadata, implementing replacement and insertion sequencing rules.

## Reuse Pointers

- `src/full_report/slicer.py`: Re-use `CbmDefectSliceMetadata` and `CbmDefectHeaderParser` for Table 1 equipment/defect parsing and D37 naming tokens.
- `src/quick_report/cbm_family.py` & `src/quick_report/models.py`: Re-use `CbmDefectRecord` and `CbmEquipmentCategory`.
- `src/full_report/models.py`: Re-use `SwitchgearCategory`, `is_tx_feeder()`, and domain scan models.

## Allowed Scaffolding

- Deep policy class `DefectInterleavingPolicy` in `src/full_report/interleaving.py`.
- Dataclasses and enums in `src/full_report/interleaving.py`: `InterleavingActionType` (`REPLACE`, `APPEND_AFTER`, `INSERT_BEHIND`, `ORPHAN_APPEND`), `InterleavingAction`, `InterleavedPart`.
- Orphan defect collector and logging utilities.
- Unit test suite `tests/test_full_report_defect_interleaving.py` validating interleaving across Talapia (FP F2 defect), Cenderawasih No.1 (RMU TX fuse replacement), and Telekom Tanah Putih (TEV appends).
