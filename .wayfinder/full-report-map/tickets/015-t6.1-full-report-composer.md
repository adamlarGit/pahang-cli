# 015: T6.1 Implement FullReportComposer Reusing WordComCompiler

## Parent

[Full Report Generation Workflow Map](../map.md)

## GitHub Issue

[#34](https://github.com/adamlarGit/pahang-cli/issues/34)

## Branch Strategy

Implemented directly on the single unified Full Report feature branch (no per-ticket branches).

## What to build

`FullReportComposer` module in `src/full_report/composer.py` that iterates parts from `FullReportStationPlan`, delegates rendering to stage renderers, and compiles the final deliverable into `FULL REPORT/<STATION>/<MONTH>/<DATE>/<STEM>.docx` by reusing `WordComDocumentCompiler` directly as-is.

## Reuse Pointers

- `src/quick_report/compiler.py`: Directly re-use `WordComDocumentCompiler`, `FakeDocumentCompiler`, and `DocumentCompiler` Protocol as-is per D40 (pure hard page breaks, zero margin modifications).
- `src/quick_report/com_session.py`: Re-use `BatchComSession` for Word COM application lifecycle.
- `src/full_report/plan_builder.py`: Re-use `FullReportStationPlan` and `PlanPartItem`.
- `src/core/normalizers.py`: Re-use `format_month_folder()`.

## Allowed Scaffolding

- Orchestrator class `FullReportComposer` in `src/full_report/composer.py`.
- Result dataclass `FullReportCompilationResult` in `src/full_report/composer.py`.
- Temporary working directory lifecycle manager with `--keep-temp` support per D14.
- Unit test suite `tests/test_full_report_composer.py` using `FakeDocumentCompiler` for fast headless execution.

## Acceptance criteria

- [ ] Implements `FullReportComposer(compiler: DocumentCompiler | None = None)`.
- [ ] Supports swappable compiler seam (`WordComDocumentCompiler` vs `FakeDocumentCompiler`).
- [ ] Compiles all planned parts into master document via `compiler.compile(parts, output_path)`.
- [ ] Automatically cleans up `temp_parts/` in a `finally` block unless `--keep-temp` is set.
- [ ] Unit tests verifying compilation flow with `FakeDocumentCompiler`.
