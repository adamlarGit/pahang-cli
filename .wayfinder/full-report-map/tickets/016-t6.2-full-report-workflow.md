# 016: T6.2 Implement FullReportWorkflow Deep Module

## Parent

[Full Report Generation Workflow Map](../map.md)

## GitHub Issue

[#35](https://github.com/adamlarGit/pahang-cli/issues/35)

## Branch Strategy

Implemented directly on the single unified Full Report feature branch (no per-ticket branches).

## What to build

`FullReportWorkflow` deep module in `src/workflows/full_report.py` exposing `inspect(target, environment)` and `generate(target, environment, ...)` with pre-flight Quick Report integrity validation and batch resilience policy.

## Reuse Pointers

- `src/quick_report/workflow.py`: Mirror architectural conventions (`inspect()` without disk side effects, `generate()` with batching, progress sinks, and telemetry schemas).
- `src/full_report/preflight.py`: Re-use `validate_finalized_quick_report()` and `PreFlightValidationResult` for upfront fail-fast checks per D41.
- `src/full_report/composer.py`: Re-use `FullReportComposer`.
- `src/full_report/plan_builder.py`: Re-use `FullReportPlanBuilder`.
- `src/quick_report/com_session.py`: Re-use `BatchComSession` to share a single Word COM instance across the batch run.

## Allowed Scaffolding

- Deep module class `FullReportWorkflow` in `src/workflows/full_report.py`.
- Dataclasses in `src/workflows/full_report.py`: `FullReportSubstationTelemetry`, `FullReportStationExecutionResult`, `FullReportBatchResult`.
- Batch isolation resilience handler capturing per-station failures into `result.errors` without aborting other stations.
- Unit test suite `tests/test_full_report_workflow.py` testing dry-run inspection, single substation generation, and mixed batch success/failure.

## Acceptance criteria

- [ ] Implements `inspect()` discovering substations, validating Quick Report presence/integrity, and returning inspection telemetry without disk writes.
- [ ] Implements `generate()` establishing a single `BatchComSession` context across all batch substations.
- [ ] Implements `SubstationIsolatedBatchResiliencePolicy`: errors on one station are captured in `result.errors` while remaining stations continue.
- [ ] Reports progress through `progress_sink` callbacks.
- [ ] Comprehensive unit tests covering single station, batch success, and partial failure modes.
