# 003: T1.3a Implement DocumentSlicer Core, Slicing Protocol & Section Boundary Extraction

## Parent

[Full Report Generation Workflow Map](../map.md)

## Branch Strategy

Implemented directly on the single unified Full Report feature branch (no per-ticket branches).

## What to build

The core `DocumentSlicer(Protocol)`, headless `FakeDocumentSlicer`, and production `WordComDocumentSlicer` that opens the finalized Quick Report in Microsoft Word, slices out static sections (`front_page.docx`, `vi_summary.docx`, `condition_pages.docx`, `vi_defect_pages.docx`, `sticker_page.docx`) into `.temp/temp_parts/<STATION>/`, and applies native Word COM Find & Replace on the front page to transform the title to `"FULL SCANNING REPORT"`.

## Acceptance criteria

- [x] `DocumentSlicer(Protocol)` defined with `FakeDocumentSlicer` for headless unit testing.
- [x] `WordComDocumentSlicer` locates boundary paragraphs per D16 and slices parts cleanly.
- [x] Front page title transformed via Word COM `Find.Execute(FindText="QUICK SCANNING REPORT", ReplaceWith="FULL SCANNING REPORT", Replace=2)` per D46.
- [x] DrawingML shapes and FLIR ActiveX controls are preserved intact in sliced `.docx` parts.
- [x] Sliced files saved to `.temp/temp_parts/<STATION>/` with clean cleanup and `--keep-temp` support.
- [x] Headless unit tests validating section slicing using `FakeDocumentSlicer`.
