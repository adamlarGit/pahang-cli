# 002: T1.2 Pre-Flight Integrity Validation for Finalized Quick Report

## Parent

[Full Report Generation Workflow Map](../map.md)

## Branch Strategy

Implemented directly on the single unified Full Report feature branch (no per-ticket branches).

## What to build

A fast, pure-Python pre-flight integrity validator that checks whether the finalized Quick Report `.docx` exists on disk, exceeds the 1.0 MB file size floor, and contains at least 8 media files inside `word/media/` before allowing Full Report generation or Word COM slicing to proceed.

## Acceptance criteria

- [ ] Validates presence of `QUICK REPORT/<STATION>/<MONTH>/<DATE>/<STEM>.docx`.
- [ ] Enforces file size floor >= 1.0 MB, rejecting empty or unpopulated templates.
- [ ] Enforces `word/media/` count >= 8 images via standard `zipfile.ZipFile` inspection.
- [ ] Returns structured `PreFlightValidationResult` with clear error diagnostics if unready.
- [ ] Fails fast before any Word COM process or slicing automation is spawned.
- [ ] Comprehensive unit tests with valid, undersized, and missing mock docx archives.
