Detailed CBM Defect Generation Pipeline

📌 What is a CBM Defect Page?

Condition-Based Monitoring (CBM) defect pages document physical anomalies detected via Infrared Thermography (IR), Airborne Ultrasound (US), or Transient Earth Voltage (TEV). Unlike visual defects, CBM defects require specific equipment family grouping (e.g., Switchgear panels vs Transformer HV/LV sides) and technical diagnostic measurements.

🎯 Core Architectural Principles
  • Decoupled Planning: Logic plans page structure prior to rendering docx files.
  • Strict Schema Mapping: Each family maps defect fields into distinct Jinja namespace dictionaries.
  • Preserving Undefined: Placeholders without data remain visible tags without breaking the layout.

1. CbmDefectPlanner cbm_defect_planner.py

Accepts raw defects for a substation and checks template availability before constructing an execution plan.

  • Filters defects per family spec (case-insensitive equipment & tech match).
  • Groups defects by specific equipment item name (e.g. RMU SF6 Feeder 1).
  • Designates the first defect as the Overview record and maps sub-defects to detail roles.
  • Returns immutable CbmDefectFamilyPlan objects.
2. CbmDefectPageBuilder cbm_defect_pages.py

Converts family plans into ordered, renderable page plans with generated docx filenames.

  • Overview Filename: 001_3 SWG OVERVIEW.docx
  • Detail Filename: 001_3 SWG RMU SF6_grp1_part1.docx
  • Builds context per page combining substation pe_info and formatted family dictionary.

PreservingUndefined Resilience

Uses custom Jinja Undefined subclass PreservingUndefined:

  • If a Jinja tag (e.g. {{ panel.breakerstatus }}) has no data, it stays rendered as {{ panel.breakerstatus }} rather than crashing or disappearing.
  • Explicit None or empty strings are automatically converted to "-".
  • Prevents Word document table layout corruption.
