Quick Report Generation Workflow

Complete End-to-End Process Breakdown: 6-Stage ETL Engine, 7-Part Document Renderer, and Microsoft Word COM Assembly

End-to-End Architectural Data Flow

🎯 Key Capabilities

  • Multi-technology diagnostic binding (IR, US, TEV, Visual).
  • Automatic 3-pair equipment layout chunking & photo aspect ratio fitting.
  • Canonical defect status suffix generation: (IR+US+TEV+VI).
  • Resilient per-station batch processing with zero-loss error isolation.

📁 Workstation Directory Model

  • Source: TESTSHEET/<STATION>/<MONTH>/<DATE>/
  • Photos: RAW MATERIAL/<STATION>/<MONTH>/<DATE>/
  • Output: QUICK REPORT/<STATION>/<MONTH>/<DATE>/
  • Filename: 001. PE BANJIR (IR+US+VI).docx

The 6-Stage ETL Engine

1
User Selection & Request Initialization
src/project_workflow_actions.py

The user triggers Quick Report generation from the CLI menu QuickReportAction.

  • Folder Mode: Interactively select target date folder under TESTSHEET/.
  • Manual FL Mode: Input comma-separated Functional Locations.
  • Template Wiring: Automatically loads MASTER_SUBSTATION_CONDITION.docx.
request = QuickReportRequest(
  mode=QuickReportMode.FOLDER,
  target_folders=(selected_path,),
  substation_condition_template_path=cond_tmpl
)
2
Package Discovery & Defect Extraction
src/quick_report/extractor.py

The QuickReportExtractor performs pure Read I/O discovery across the workstation directory structure.

  • Discovers digital testsheet packages via SubstationTestsheetRepository.
  • Parses substation metadata (PE #, ERMS Name, Site Name, FL, Date, GPS, Ambient/Humidity).
  • Queries MasterQr03DefectRepository for CBM defects (QR03 CBA) & Visual defects (QR03 VI).
cbm_defects, vi_defects = self.extractor.extract_defects(
  pkg, environment
)
3
Domain Filtering & Precondition Audit
src/quick_report/filter.py

Filters discovered packages using QuickReportFilter and validates required docx template preconditions.

  • Verifies availability of VI Front Page, Sticker Page, and Substation Condition templates.
  • Filters out incomplete packages or non-matching FLs.
filtered_pkgs = self.filter_stage.filter(
  packages, request
)
4
Defect Suffix Calculation & Execution Planning
src/quick_report/transformer.py

Transforms raw extracted data into an immutable QuickReportStationPlan.

  • Defect Suffix Rule: Calculates canonical suffix order (IR+US+TEV+VI) based on present defect findings.
  • Pahang Stem Naming: Constructs output filename omitting date: {pe_number:03d}. {sanitized_name}{suffix}.docx.
  • CBM Family Planner: Groups CBM defects into detail page plans using CbmDefectPlanner.
plan = self.transformer.transform(
  pkg, cbm_defects, vi_defects, env
)
5
Multi-Part Document Render Stage
src/quick_report/composer.py

Renders each sub-document section into independent temporary .docx files inside temp_parts/.

  • Executes modular render functions for Front Page, Summaries, CBM Families, Condition Grid, VI Cards, and Sticker Page.
  • Passes sized images (e.g. width=Mm(120)) via docxtpl.InlineImage.
parts = self._generate_parts(plan, temp_dir)
6
Document Compilation & Temporary Cleanup
src/quick_report/composer.py

Compiles individual docx parts into the final report via _compile_document.

  • Uses Microsoft Word COM Automation (win32com) with programmatic page breaks and paragraph trimming.
  • Falls back to docxcompose.Composer if Word COM is uninstalled/unavailable.
  • Cleans up temp_parts/ and triggers garbage collection.
self._compile_document(parts, plan.final_output_path)

7-Part Document Assembly Sequence

Quick Report documents are compiled sequentially part-by-part. Below is the complete 7-part composition specification.

Part 1
Front Cover Page
Main metadata page with station name, PE number, ERMS FL, site FL, date (DD MMM YYYY), and technology scope rating (IR / IR+US / IR+US+TEV).
templates/QUICK REPORT/1. FRONT PAGE...docx
Part 2A
CBM Tech Defect Summary
Rendered only if CBM defects exist. Displays CBM technology summary table listing findings across IR, US, and TEV.
templates/QUICK REPORT/CBM DEFECT SUMMARY.docx
Part 2B
VI Defect Summary
Rendered only if VI defects exist. High-level summary table of all physical & visual defects found during inspection.
templates/QUICK REPORT/2. VI SUMMARY...docx
Part 3
CBM Defect Family Detail Pages
Equipment family overview and detailed individual defect cards for Switchgear, Transformers, LVDB, Black Box, and Battery Bank.
templates/QUICK REPORT/DEFECT IR/*.docx
Part 4
Substation Condition Pages
3-pair per page grid showing substation overview, signboard, switchgear, transformer, feeder pillar, RTU, battery charger, EFI, and oil level indicator photos.
templates/QUICK REPORT/SUBSTATION CONFIGURATION/*.docx
Part 5
VI Defect Card Pages
Individual visual inspection defect detail pages containing defect photos, precise location, severity, and remediation action.
templates/QUICK REPORT/10. VISUAL DEFECT...docx
Part 6 (Mandatory)
Physical Sticker Placement Page
Mandatory final page providing designated zone for attaching physical station QR code / barcode stickers.
templates/QUICK REPORT/STICKER PAGE.docx

Photo Embedding & Word COM Compilation Engine

📷 Photo Range Matching & Sizing

Photos are extracted from RAW MATERIAL/ using stem matching logic. docxtpl.InlineImage embeds images with explicit width constraints to automatically preserve original aspect ratio.

  • Front Page Photo: width=Mm(120)
  • Defect Card Photo: width=Mm(68)
  • Condition Pair Photo: width=Mm(75)
  • Missing Photo Fallback: Injects non-blocking warning and default blank placeholder.

🖥️ Word COM Compiler vs docxcompose

Located in _compile_document, compilation prioritizes native Word COM.

Win32 Word COM Engine
Executes win32com.client.Dispatch("Word.Application"). Opens parts, deletes empty trailing paragraphs from each part, inserts page break (wdPageBreak=7), pastes content, and saves.
Fallback: docxcompose
If Word COM is not installed, uses Composer(master_doc).append(part_doc) programmatically in pure Python.
